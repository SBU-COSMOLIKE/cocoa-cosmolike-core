Dated development history, removed from the project test READMEs (they

# The 2026-09-28 refreeze: non-Limber C_gg growth fix

## The defect

Below l = 150 cosmolike's `C_cl_tomo` computes

    C_l = C_l^FFTLog(P_lin) + C_l^Limber(P_delta) - C_l^Limber(P_lin),

an exact FFTLog projection of the linear power spectrum plus, in the
Limber approximation, what linear theory misses. Where the Limber
approximation holds (high l) the first and third terms must converge
to the same number and cancel, leaving the Limber C_gg. The FFTLog
term needs separable growth, D(z1) D(z2) P_lin(k, z=0), but the
subtracted Limber term used CAMB's P_lin(k, z), whose growth depends
on scale with massive neutrinos: the two differ by 0.7% at z = 0.3 and
1.6% at z = 1, so the pair never cancelled. Every C_gg below the
switch to Limber carried a -0.85% to -1.6% offset, and the 1% early
exit fired near l = 50, where the decaying non-Limber correction
happened to cancel the offset, dropping a real 1.3% to 2.2% correction
for the highest lens bins. With the fix the subtracted term uses
D(a)^2 P_lin(k, z=0), and the two terms agree to 0.02% to 0.17% at
l = 149. The fix changes w(theta) only; cosmic shear and
galaxy-galaxy lensing are unchanged.

On 2026-09-28 the fix landed, the shipped data vectors were
regenerated with the fixed code, the galaxy-galaxy lensing default
switched to non-Limber (`adopt_limber_gs: 0`), and every project
snapshot was refrozen; the regenerated vectors' chi2 values became the
new references, recorded in each `frozen/reference_chi2.json` `_meta`
block.

## The current implementation

`C_cl_tomo` now anchors the separable spectrum per lens bin instead of
at z = 0: (D(a)/D(a_piv))^2 P_lin(k, a_piv), with a_piv = 1/(1+zbar)
and zbar the bin's mean redshift, so the separable form is exact at
that redshift. The derivation and consequences live in the comments of
`C_cl_tomo` in `cosmolike/cosmo2D.c`; the related CCL-side study of
separable-growth offsets is in the CCL-benchmark repository.

# The 2026-11-04 roman_kl refreeze: CAMB halofit tolerance

## The cause

Stock CAMB's halofit locates the nonlinear scale with a bisection
that stops at |sigma(R) - 1| <= 1e-3. The stopping point jumps
between nearby cosmologies, shifting the nonlinear P(k) by ~0.3%:
enough to move a frozen clustering reference beyond the 0.2 chi2
limit, and enough to put jumps into Fisher derivative columns. The
`PATCH_CAMB_HALOFIT_TOLERANCE` installation key tightens the stop to
1e-7; Cocoa applies the patch by default since commit `6b5e117b`
(2026-11-08, `set_installation_options.sh`).

## The refreeze

roman_kl's references were refrozen on 2026-11-04 on the patched
CAMB. On stock CAMB its references move by Delta chi2 = 0.76 (3x2pt)
and 0.75 (2x2pt), beyond the 0.2 limit; cosmic shear moves by 0.009.
The refreeze regenerated the model vectors, `reference_chi2.json` and
the manifest, re-pinned `test_nonlimber_gg` (measured 47.09 ->
46.6845) and `test_nonlimber_lowrank_gg` (`DCHI2_MEASURED`
4.978820e-03 -> 4.974792e-03), set the frozen EMUL2 yamls to device
"cpu", and added README warnings. It was verified on 2026-11-14
against the current core (cosmolike_core `4f9739d`) with the patched
CAMB installed - test_example1, test_example2, test_example2_2x2pt,
test_nonlimber_gg, test_nonlimber_lowrank_gg and test_baryons pass
(21 tests), all 51 manifest hashes match - and committed as roman_kl
`35a2ed2` on branch `lowrank_fftlog`.

## Open: the other projects' references predate the patch

Every other project's references were frozen before the patch became
the default, so each must be checked on the patched CAMB project by
project. lsst_y1 and lssty1xdesi pass on it today; the remaining
projects' quick data-vector tests run when their setting-sequence
test bindings land. A project whose clustering or lensing reference
moves beyond the 0.2 limit needs its own refreeze on the patched
CAMB, as roman_kl did. The patch also matters for Fisher derivatives:
publication-tier derivative settings assume it.
