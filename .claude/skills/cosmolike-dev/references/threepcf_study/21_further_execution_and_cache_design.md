# 21. Further reductions in repeated work: transforms, covariance batches, and Fisher calls

> **Archive status.** This source study records design proposals and validation requirements, not completed features. Read the [maintained implementation status](../threepcf.md) first. Both the mean and its covariance belong in `cosmolike/3pcf/`; earlier destination proposals using `fastnc/` or `covariances/` are superseded.

This source pass identifies work that can be removed before deciding how many CPU workers to use. Some opportunities are small and exact, such as duplicate inverse-transform orders at one mode. Others change the organization of the calculation: an aperture-only prediction can apply the transpose of its fixed transform to the measurement weights once, then evaluate dot products instead of reconstructing every natural component at every model point. The latter requires a derived discrete operator and numerical comparisons; it is a proposed implementation, not an existing measured acceleration.

The evidence uses fastnc TATT `7b2336ce37a909bed51f07f32a2a4f096e71b6ce`, desy6-3pcf `fd59fe4fee694d359453d5f573d6a4a55a47a812`, the covariance source recorded in Chapter 15, and core `0c0cf3838852396933c7f49550e35917dad0537c`. Existing local modifications remain untouched. The applicable core skill and its cache-invalidation reference require separate checks for allocation sizes and stored values; that rule informs the ownership table below. No implementation, scientific-module imports, numerical calculations, or timing exercises were performed. [Core skill](../../SKILL.md); [invalidation requirements](../state_invalidation.md).

## 1. Four source details identify avoidable setup inside repeated calls

**The Y6 triplet loop rebuilds fixed FFT geometry.** Its `compute` method calls `nc.set_bispectrum(bs)` for each requested source combination or redshift slice. That setter always calls `set_fftgrid`, which tunes the grid and builds its meshes. For one request with unchanged angular configuration, the bispectrum values change between combinations but the transform geometry does not. The port should bind a prepared geometry object once and update the spectrum values separately. A changed scale range, tuning rule, bin edge, or transform option must still rebuild that geometry. [Triplet loop](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/desy6_3pcf/fastnc_backend.py#L242-L274); [unconditional grid preparation](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/fastnc.py#L124-L135).

**Multipole interpolation repeats its query geometry for every order.** `kappa_bispectrum_multipole` constructs a new interpolator for each $`L`$, copies and folds $`\psi`$, takes logarithms of the query coordinates, and corrects their edges. On fixed input and query grids these operations give the same brackets and weights for every order and source combination. Store the interpolation stencil, meaning the table indices and interpolation weights for each query, once. Four corners suffice for the two-dimensional linear interpolation. The earlier three-dimensional signed TATT interpolation similarly uses eight corners for its default linear method. Compact storage can retain the lower cell and the two or three coordinate fractions instead of every corner weight, trading a few products for fewer memory reads. This does not apply unchanged to nonuniform grids: their cell locations must first be found using the actual grid. [Multipole query loop](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/bispectrum.py#L1053-L1087); [signed three-dimensional interpolation](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/bispectrum.py#L963-L994).

**A particular mode repeats two inverse transforms.** The source's four Bessel-order pairs at $`M=1`$, after taking absolute values, are $`(2,4),(2,0),(2,4),(2,0)`$. Their negative-order sign factors are also equal within each pair. Thus only two inverse results are needed for that mode before applying the existing component-specific storage and transposes. This follows directly from the displayed order formulas; it does not assume that the input matrix is symmetric. With all four components and $`M_{\max}\ge1`$, it removes two inverse transforms from the otherwise $`4(M_{\max}+1)`$ calls. The saving is bounded and should not be described as the main acceleration. [Order selection and storage](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/fastnc.py#L358-L393).

**The power readers rebuild splines at each call.** The IA functions construct splines for log power and growth inside `get_interpolated_pklin` and `get_interpolated_pknl`; `get_ia_bispectra` requests three power arrays. Prepare the selected spectrum's spline representation, endpoint slopes, and growth interpolation when their inputs change, then share those readers across the triangle tiles. Preserve the upstream normalization and extrapolation convention when reproducing its result. This is distinct from replacing its nonlinear redshift evolution with the core's alternative prescription. [Reader construction](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/ia_bispectra.py#L79-L129); [three power requests](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/ia_bispectra.py#L614-L622).

## 2. A task and ownership table for an actual evaluation

The following objects separate reusable values from writable scratch. A numerical setting is part of a stored result's definition, even when it is not a physical parameter. The table therefore specifies the event that changes an object rather than saying only that it is “static.”

| Object and preparation task | Reuse boundary | Owner and parallel use | Required key details beyond array dimensions |
|---|---|---|---|
| Tuned angular/FFT grids and triangle coordinate maps | All models using one measurement configuration | Immutable geometry owner; all workers read | Actual tuned nodes, tuning convention, requested bins, scale bounds, padding, downsampling |
| Two- and three-dimensional interpolation stencils | All values on those same grids | Geometry owner; disjoint query blocks evaluated in parallel | Input and query nodes, folding, edge correction, interpolation method |
| Coupling and Bessel multipliers | All cosmologies at fixed transform definition | Immutable arrays; transform tasks read | Orders, FFT biases, bin-averaging widths, Fourier origins, taper choice |
| Aperture dual weights derived below | All model values under the same finite estimator | Measurement owner; filters can be prepared independently | Component convention, phases, triangle mask, aperture radii, every preceding linear operation |
| Power and growth interpolation representation | One installed cosmology and provider state | Model owner; prepared before worker entry | Actual supplied arrays, normalization, density field, units, extrapolation, baryon prescription |
| Halo abundance, concentration, and profile blocks | One model on one mass/redshift/wavenumber block | Model workspace; workers own profile rows or mass chunks | Halo mass definition, fit options, mass limits, neutrino prescription, all physical grids |
| Source and IA radial coefficients | Fixed cosmology and relevant source/nuisance state | Radial owner; independent bin/node outputs | Source histograms, shifts, normalization, IA pivot, slopes, amplitudes, density-weighting convention |
| Covariance callback geometry and model-dependent values | One integration batch and one physical term | Batch owner; read-only shared values after preparation | Integration coordinates, selected term, model prescription, domain mapping |
| FFT and contraction scratch | Reusable allocation, contents overwritten each task | One slice per worker; never a shared output buffer | Transform dimensions, alignment, strides, maximum allocated worker count |
| Saved Fisher predictions | An identical requested prediction | Evaluation store outside mutable core state | Parameter values, provider/numerical state, observable ordering, masks, model and source revision |

A source-bin change illustrates why these divisions matter. At fixed cosmology it changes lensing efficiencies and source weights, but need not change the matter bispectrum at a given physical triangle. An IA amplitude change can reuse amplitude-independent physical terms, but must refresh their coefficients and every dependent prediction. A new number of source bins can resize an output even if its old value key happens to match. The core's two-tier rule addresses the latter failure explicitly; a single “model changed” flag cannot express all three situations.

The Y6 `update` method currently sends every input category through setters and recomputes kernels. That behavior provides no selective cache proof. The port should compare the relevant input category and publish its changed state only after preparation is finished. Inputs must be owned or immutable: upstream linear-power normalization modifies its supplied array, so an address or object identity is not evidence that the numerical spectrum is unchanged. [Backend update](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/desy6_3pcf/fastnc_backend.py#L204-L228); [input mutation](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/ia_bispectra.py#L38-L77).

## 3. Move the aperture weights backward through the fixed transform

Chapter 4 proposes combining aperture weights with the opening-angle reconstruction. The same reasoning can extend through the FFTs. This construction complements Chapter 20's analytic integral reductions: it reproduces the specified numerical forward prediction, including its grid and truncations. Establishing its equality to the catalogue estimator, and deriving that estimator's covariance, remain separate tasks; see [Chapter 22](22_stress_test_of_reductions.md). Let $`h_M`$ contain the real $`H_M(\ell_1,\ell_2)`$ values in the inspected Legendre calculation and let $`T_M`$ denote the fixed discrete map from that array to the real and imaginary parts of the natural components. With the default zero input-extrapolation counts, it includes input bias powers, forward FFT, Bessel multipliers, inverse FFT, truncation, downsampling, component transposes, negative-order signs, opening-angle reconstruction, and projection phases. Let $`a_f`$ contain the final real-linear weights for aperture output $`f`$. Then

```math
y_f=\sum_M a_f^{\mathsf T}T_M h_M
   =\sum_M d_{fM}^{\mathsf T}h_M,
\qquad d_{fM}=T_M^{\mathsf T}a_f.
```

The vector $`d_{fM}`$ is the measurement weight moved backward through the calculation. It is often called a dual weight. Computing it once lets a later model evaluation calculate the required aperture values by dot products with $`H_M`$. The proposal removes repeated transforms from this aperture-only stage without changing the finite integration domain or the number of measured aperture values. It still computes the bispectrum and the mode coupling that produce $`H_M`$. A natural-component diagnostic requests the ordinary forward calculation instead. [Transform sequence](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/fastnc.py#L335-L409); [two-Bessel implementation](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/twobessel.py#L159-L213); [aperture contraction](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/desy6_3pcf/map3.py#L98-L126).

Real-linear is a necessary qualification. The implementation conjugates coefficients, stores only part of a real FFT, rearranges frequencies, and finally takes a real part. Taking a complex-conjugate transpose of an incompletely specified complex matrix can therefore miss factors or duplicate endpoint modes. Derive the adjoint in a real representation, or derive the half-spectrum weights including the zero and Nyquist modes. The zero-$`M`$ component assignments also share array slots: the transpose must follow the actual final assignments rather than adding both overwritten contributions. This is an algebraic identity for the chosen discretization; reordered floating-point operations need not be bitwise identical. Dot-product tests between forward and transpose operations, followed by complete-vector and derivative comparisons, are future acceptance requirements.

The endpoint treatment must be traced explicitly. Fixed zero padding is linear, and its transpose extracts the original input cells. A fixed taper would also be linear. The pinned source, however, computes a tapered coefficient array and returns the untapered array; the reproduction operator must follow that return value unless the authors separately adopt a correction. Nonzero input extrapolation is different: it takes the logarithm of the input values, extrapolates their endpoint slopes, and exponentiates. That is nonlinear and cannot be absorbed into a model-independent weight on the original $`H_M`$. Either retain the default disabled extrapolation or apply the dual weights only after the model-dependent extrapolated array has been constructed. The key must record both extrapolation counts and the actual taper behavior. [Padding and returned coefficients](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/twobessel.py#L17-L98); [logarithmic extrapolation](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/twobessel.py#L316-L338).

The storage tradeoff is concrete. Dense real dual weights require approximately $`8N_f(M_{\max}+1)N_1N_2`$ bytes. For five filters, $`M_{\max}=100`$, and hypothetical actual grids of $`150\times150`$, that is 90.9 MB. The configured `nfft=150` is a nominal grid-size request; use the tuned dimensions when estimating real storage. Tiles over modes or filters can limit working memory. Constructing a full matrix $`T_M`$ by applying it to every basis vector would waste this advantage: the transpose must be applied stage by stage to the small set of filter weights.

There is a strict boundary to pushing these weights farther backward. Signed linear TATT interpolation, multipole decomposition, and mode coupling are linear in their input values on fixed grids. Their transposes can also act on the weights. The matter branch instead stores $`\log B`$ and returns $`\exp[\operatorname{interp}(\log B)]`$. That operation is nonlinear in $`B`$; projection and radial summation cannot be commuted through it as though it were a matrix. An exact discrete reproduction must stop the transpose at that boundary, or separately justify a changed interpolation representation. [Different interpolation branches](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/bispectrum.py#L930-L994).

## 4. Covariance callbacks have two distinct batch axes

The inspected CPU covariance callbacks already receive many integration points, but explicitly require one output component. They parallelize over points and recompute the requested aperture entry at each point. A port can instead evaluate a small group of covariance entries at the same coordinates. Geometry, power spectra, bispectrum terms, and halo profiles are shared; only filter and catalog factors may differ. For $`N_p`$ nodes and $`N_o`$ outputs, separate calls can require $`N_pN_o`$ evaluations of a shared physical quantity, whereas a common batch needs $`N_p`$ such evaluations plus the $`N_pN_o`$ inexpensive output combinations. This count is conditional on shared coordinates and physical inputs. [Scalar-output callback](https://github.com/sheydenreich/threepoint/blob/08de9645a7294092995e5aeaf7b36e48e8fc10a3/classed_version/apertureStatisticsCovariance.cpp#L407).

Adaptive integration complicates the choice. Different entries can need different refinement, so one large output vector may force every entry to follow the most demanding one. Relative error alone also behaves poorly for an entry near zero. Group entries with similar aperture scales and common domains, retain error control for each component, and inspect both diagonal and signed cross entries. The upstream cutoff can depend on the smallest aperture radius, so sharing a domain across entries must preserve their cutoffs or demonstrate convergence of a common enlarged domain. Merely evaluating all outputs on whichever nodes the first entry happened to request is not an accuracy guarantee.

OpenMP and SIMD should own different parts of this batch deliberately. A worker may own a block of integration points and prepare their common physical quantities. Within that block, SIMD lanes can represent several triangles while computing geometry, then several output entries while applying filters. Packing a small output tile with entries adjacent in memory permits broadcast of one expensive physical value to several lanes. A radial contraction can similarly put four aperture or tomographic outputs in four lanes, each retaining its own ordered node sum. SIMD over nodes is another option, but its horizontal reduction changes addition order. These layouts are choices at a phase boundary, not reasons to transpose the entire calculation repeatedly.

The parent covariance algorithms decide which integrals remain after analytic reductions. Callback batching applies to those remaining integrals. It should not reconstruct high-dimensional Fourier integrals that the filtered-profile formulation has already removed, nor call a shared static FFT builder independently from each node. Preparation completes before integration workers start; scratch belongs to workers and output tiles have one writer.

## 5. Share mean and covariance ingredients without equating their models

Power tables, source efficiencies, angular filters, and some halo profiles can serve both the mean and covariance. A bispectrum used in a covariance product can also reuse a prepared triangle table if the argument grid, redshift, density field, power prescription, intrinsic-alignment content, and baryonic correction agree. Equality of the name “bispectrum” or the array shape is insufficient. The existing mean may use BiHalofit, whereas a higher-order covariance term may be defined through one-halo profiles or tree-level correlations between halos. Those are different physical inputs even at one cosmology.

The reuse boundary should be an input record identifying these choices. Mean and covariance consume an immutable record and their own output storage. A fixed covariance in the Fisher forecast retains its fiducial record when a derivative changes the mean cosmology; it must not silently refresh because a shared model cache changed. Conversely, a requested covariance derivative must invalidate its model-dependent tables. Sharing a mass table does not imply that a power response supplies a bispectrum response. The latter is a derivative of a different statistic and needs its specified physical terms.

Coordinate reuse has a second boundary. The angular grid can stay fixed while the physical query $`k=(\ell+\Delta\ell)/\chi(z)`$ changes with redshift or cosmology. A cached angular interpolation stencil remains valid on its unchanged angular grids, but a power-table stencil at these physical wavenumbers does not. Fastnc explicitly constructs these $`k`$ arrays in the radial calculation. A physical-$`k`$ table may be smooth in redshift while the path at fixed $`\ell`$ crosses sharp power-spectrum structure; making more points from an already under-resolved interpolant cannot recover that structure. Separate the immutable angular stencil from the cosmology-dependent physical query and test the latter over the complete projection. The core's optimization record identifies this same distinction and rejects specific coarse fixed-$`\ell`$ tables. [Physical-wavenumber construction](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/bispectrum.py#L721-L740); [core coordinate warning](../covariance_optimization_review.md).

Some additional reuse is within the current covariance driver itself. It calls the halo-moment preparation for central wavenumbers and again for displaced wavenumbers needed by a slope. Both calls prepare the same abundance, bias, and concentration at the same mass and redshift nodes. A proposed halo workspace can prepare those quantities once, evaluate the union of central and displaced profile rows, and compute pair moments only on the central grid. It need not allocate all pairs of the enlarged grid. This saves repeated preparation while preserving the current finite-difference prescription. [Central and shifted calls](../../../../../cosmolike_notebook_utils/covariance/survey.py).

## 6. Organize Fisher requests to preserve expensive state

The core five-point derivative helper evaluates four displaced vectors per parameter; its center has zero derivative weight. The separate stencil-noise helper requests those same four locations and a center. Saving exact predictions can therefore reuse all four when the parameter arithmetic, model, and accuracy settings match, and share the center across parameters. For $`p`$ parameters, a combined derivative and matching noise study can use $`4p+1`$ distinct predictions instead of separately requesting $`4p+5p`$. This is a derived request count for those helpers, not a statement about CosmoSIS's different sampler. Changed step sizes generally add locations. [Derivative requests](../../../../../cosmolike_notebook_utils/fisher.py); [noise-check requests](../../../../../cosmolike_notebook_utils/fisher.py).

Schedule nuisance-only requests together at the fiducial cosmology so their prepared physical basis remains available. Source-redshift shifts need different radial weights; IA coefficients need their own recombination; multiplicative calibration can act on the uncalibrated final vector. Cosmological displacements require the affected distances, powers, growth, and physical-wavenumber queries. Retaining every large displaced bispectrum is unnecessary: store its small final prediction, and retain a bounded number of expensive model workspaces according to the request order.

Cache matching must not use a broad `allclose` test on parameter vectors. A Fisher step can deliberately be small, and treating two distinct points as equal creates an artificial zero derivative. Store exact request values and the numerical/provider definition, with canonical ownership of immutable arrays. A test intended to detect nondeterminism must bypass prediction caching; otherwise it compares a stored vector with itself and cannot reveal a race. A future evaluation record should distinguish reuse of a final prediction, reuse of geometry, and recomputation of physical terms, because these are different sources of reduced work.

The immediate design priorities from this pass are therefore specific: remove repeated geometry and interpolation setup, prepare model readers once, derive aperture dual weights through the fixed linear stages, batch remaining covariance outputs with explicit error control, and order Fisher requests by shared physical state. These actions retain CPU C, OpenMP, and SIMD as the primary design. Their accuracy and wall-clock effects remain to be checked when implementation and a quiet-machine measurement are authorized.
