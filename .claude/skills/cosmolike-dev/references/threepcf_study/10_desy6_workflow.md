# 10. Rafael's DES Y6 package and a shared Y3/Y6 forecasting interface

> **Archive status.** This source study records design proposals and validation requirements, not completed features. Read the [maintained implementation status](../threepcf.md) first. Both the mean and its covariance belong in `cosmolike/3pcf/`; earlier destination proposals using `fastnc/` or `covariances/` are superseded.

## What this repository contributes

[Rafael Gomes's `desy6-3pcf`](https://github.com/rchgomes/desy6-3pcf) supplies a survey-analysis structure that the proposed CosmoLike implementation should reuse as a reference. It contains measurement binning, a wrapper around fastnc, aperture-mass integration, redshift-slice emulation, likelihood modules, Fisher configurations, and tests. Rewriting all these pieces in C would expand the task without directly accelerating the expensive bispectrum and transform calculations. A more focused project would supply a CosmoLike C calculation behind the package's existing numerical interface, compare its arrays with the Python calculation, and then connect that calculation to Cocoa.

This chapter examines commit [`fd59fe4fee694d359453d5f573d6a4a55a47a812`](https://github.com/rchgomes/desy6-3pcf/tree/fd59fe4fee694d359453d5f573d6a4a55a47a812). Its installation instructions pin the **same** fastnc TATT commit examined elsewhere in this study, [`7b2336ce37a909bed51f07f32a2a4f096e71b6ce`](https://github.com/git-sunao/fastnc/tree/7b2336ce37a909bed51f07f32a2a4f096e71b6ce). Thus the package does not, by itself, resolve findings inside that dependency. The scientific references remain the [fastnc method paper](https://arxiv.org/abs/2407.01798), the [DES Y3 analysis](https://arxiv.org/abs/2503.03964), and the [TATT analysis](https://arxiv.org/abs/2601.09133). These distinguish a numerical method, a survey application, and an intrinsic-alignment extension; reproducing one does not establish the other two.

Everything below follows from reading source and configuration files. No tests, imports, forecasts, training jobs, or timing experiments were executed. The package is evidence of an analysis implementation, rather than evidence that a DES Y6 scientific analysis has passed validation: its [README explicitly lists no scale cuts or two-point compression](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/README.md#L12-L25), its priors are placeholders, and its data products are external.

## Preserve two distinct survey definitions

The Y6 defaults are 25 logarithmic bins for each triangle side between 1 and 150 arcmin, 100 opening-angle bins between zero and $`\pi`$, and five equal aperture radii, 3, 5, 10, 20, and 40 arcmin. An aperture statistic averages shear with a radial filter; its radius is not the same quantity as the two triangle-side coordinates used to measure the three-point correlation. Four source-redshift bins give $`\binom{4+3-1}{3}=20`$ unordered tomographic triplets. Five aperture radii therefore produce 100 entries before cuts. These definitions are explicit in [binning.py](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/desy6_3pcf/binning.py#L18-L45).

The requested Y3 Fisher calculation must retain its own measurement definition, including the 80-entry equal-aperture vector discussed in this study, until an explicitly different Y3 observable is chosen. Reading Y3 files through this package does not turn their four aperture radii into Y6's five. The [FITS reader deliberately retains the Y3 layout](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/desy6_3pcf/datavector.py#L1-L8), so a common adapter is plausible. Each survey still needs its own source distributions, masks, aperture radii, calibration priors, covariance, and ordering of entries. Their input records should also state whether the two-point data are compressed and how the cross-covariance was transformed.

For an advanced undergraduate, the reason is direct: a Fisher matrix measures how a specified experiment distinguishes nearby models. Changing the measured quantities while keeping an old covariance does not describe that experiment. A common C engine can evaluate both surveys; the records describing the two experiments must remain separate. The package's option for every unordered combination of five aperture radii would give 35 filter triplets and 700 selected entries for four source bins. That is a different observable with different covariance requirements. It also does not enumerate all distinct unequal-filter tomographic assignments: permutation symmetry exchanges a source bin and its attached filter radius together. Sorting bin labels and radii independently can omit assignments. For example, applying the small filter to bin 1 and the large filter to bin 2 is generally different from reversing those filter assignments. Test permutations of the paired labels, including ordered IA contributions, before extending the equal-filter vector.

The representative triangle-side coordinate also needs a survey-specific check. The package uses

```math
\bar\theta=\theta_{\min}\left[\frac{2}{3}
\frac{e^{3\Delta}-1}{e^{2\Delta}-1}+\epsilon\right],
\qquad \Delta=\Delta\ln\theta,
```

where the first term assumes a uniform distribution on the sky and $`\epsilon`$ is a calibration offset. The default is zero. This expression supplies the coordinates for the aperture integral; the natural-component transform receives lower bin edges and the logarithmic width separately. These two operations must not be merged into a single point evaluation when porting. Compare their combined prediction with the actual catalogue's weighted mean separations and bin-averaged estimator, for both surveys. [Definition](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/desy6_3pcf/binning.py#L48-L71); [module assembly](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/modules/fastnc_interface.py#L58-L115).

## The existing numerical boundary is suitable for a C adapter

Only [fastnc_backend.py](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/desy6_3pcf/fastnc_backend.py#L1-L14) calls fastnc directly. Its `NaturalComponents` class takes a cosmology, power spectra, growth, source distributions, and intrinsic-alignment parameters, then returns four complex natural components for each requested tomographic triplet or redshift slice. Natural components are combinations of the three galaxy shears whose phases are defined relative to triangle geometry. They retain the information needed to form the aperture statistic.

The output shape is `(4, ntheta, ntheta, nphi)`. The adapter converts fastnc's conventions into TreeCorr's conventions through a minus sign and an interchange of components 2 and 3. For a scalar redshift slice of the matter bispectrum it also removes a residual projection factor; the TATT slice follows a different upstream normalization. These are physical and estimator conventions that must be checked component by component before comparing only the final sum. The exact operations are visible in [compute](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/desy6_3pcf/fastnc_backend.py#L242-L281).

The second interface, `LensingKernels`, returns distance and projection weights. In its conventions a projected slice quantity $`S_R(z)`$ contributes

```math
m_R^{ijk}=\int d\chi\;q_i(\chi)q_j(\chi)q_k(\chi)
\frac{(1+z)^3}{\chi}\,S_R(z).
```

Here $`R`$ denotes the aperture configuration, $`\chi`$ is comoving distance, and each $`q`$ is a lensing or source-distribution weight according to the physical component. Factors have already been absorbed into these particular $`q`$ definitions; substituting a familiar lensing kernel from another code without reconciling units would change the prediction. The input record uses $`k`$ in $`h/{\rm Mpc}`$ and power in $`({\rm Mpc}/h)^3`$, while distance is in $`{\rm Mpc}/h`$. The C adapter must document conversion to CosmoLike's internal units. [Inputs](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/desy6_3pcf/fastnc_backend.py#L38-L67); [kernel interface](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/desy6_3pcf/fastnc_backend.py#L285-L320).

A first C adapter should return these same arrays and leave the existing aperture and likelihood modules available for comparisons. A later production path can contract into aperture moments without storing every triangle. Keep the CosmoSIS calculation callable independently: importing its conventions into Cocoa should not eliminate the external calculation against which the C implementation is tested. Matching backgrounds, neutrino conventions, growth normalization, and nonlinear power is part of that comparison; an identical list of parameter names does not guarantee identical inputs.

## Which source findings this package already addresses

Several findings from `3pcf_integrator` should not be repeated as unresolved faults of this package. The following distinctions are established by reading the actual statements, although execution-based confirmation remains outstanding.

| Item | Evidence in the Y6 package | Remaining check |
|---|---|---|
| Quadratic IA redshift exponent | `alphaIA_2` receives `alpha2`, rather than `a2` as in the older integrator | Vary `alpha2` with `a2` held fixed and compare analytic redshift scaling and full-vector derivatives |
| Shared NLA configuration | Each bispectrum instance receives its own `config_IA` dictionary | Repeat matter and IA predictions in different evaluation orders and with separate worker instances |
| Unequal aperture kernels | The general expression is always used; the old `k2.all()==1` branch is absent | Compare unequal filters, permutations, and small signals with a fixed TreeCorr version |
| Repeated aperture setup | `Map3Transform` computes weights once and reuses a matrix contraction | Preserve this reuse in C; do not claim eliminating it as an additional gain over this package |
| Extra Gaussian Fisher priors | The summary script adds only priors explicitly requested by the user | Record priors already included by the sampler and reject accidental duplication |

The alpha mapping is directly comparable between the [older integrator](https://github.com/rchgomes/3pcf_integrator/blob/d6098d326dcb03bc750adcc9627119f52d928944/python/fastnc_interface.py#L151-L159) and the [Y6 backend](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/desy6_3pcf/fastnc_backend.py#L204-L223). Instance isolation is explicit at [lines 80–84](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/desy6_3pcf/fastnc_backend.py#L80-L84). Aperture weights, mirrored-triangle treatment, and the contraction appear in [map3.py](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/desy6_3pcf/map3.py#L98-L126). Its TreeCorr-derived expressions require attribution to Mike Jarvis and the relevant license, alongside the credits to Sunao Sugiyama and Rafael Gomes.

Tests are useful evidence about intended behavior, but their existence is not a numerical validation result. The [TreeCorr comparison test](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/tests/test_map3.py#L45-L64) requests relative tolerance $`10^{-10}`$ while retaining NumPy's default absolute tolerance. For a small shear statistic, that absolute tolerance can dominate. A future comparison should report both scales explicitly, rescale synthetic examples when testing relative precision, and include physical vectors. The backend tests examine kernel behavior rather than evaluate a full TATT bispectrum. They cannot close the upstream distinction between seven projected component labels and the nineteen returned kernel quantities discussed in the source audit.

## Emulation, TATT choices, and what remains outside the defaults

The emulator architecture already separates expensive slice calculations from the source-distribution integral. It predicts aperture statistics on 64 redshift slices spanning 0.005 to 2. Each prediction can then be projected for multiple source-bin triplets. This reuse explains why one need not regenerate a training set merely to change the source distribution, provided the physical input dependence and redshift support remain covered. The [execution loop](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/modules/map3_emulator.py#L85-L121) uses lensing weights for the letter `d` and source weights for `E` in each TATT label.

The package also records whether the alignment term was removed from the TATT networks. If it was, the reference matter contribution includes NLA; otherwise the reference uses pure lensing. This prevents counting the same tree-level contribution twice at the level of bookkeeping. Its equality across all seven network metadata records is checked during setup. The physical identity still needs an end-to-end test: the sum of individually projected components must match the direct calculation under the same subtraction convention. Redshift upsampling interpolates the existing slices; it cannot recover missing information outside their support or resolve a feature that was never sampled. Check source tails, shifted redshift distributions, IA exponents, and Fisher derivatives when refining the slice grid. [Metadata check](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/modules/map3_emulator.py#L45-L67).

The coefficient `Ct` is **present in the brute-force path** as an option with default zero and is forwarded to fastnc. It is not a sampled parameter in the shipped emulator design, whose five IA coordinates are `a1`, `alpha1`, `a2`, `alpha2`, and `bias_ta`. The supplied training configuration therefore inherits zero unless overridden. A nonzero or marginalized coefficient from the TATT science case requires an explicit modeling decision and a matching training or analytic reconstruction strategy. Calling the current emulator “TATT” does not establish that every parameter of the paper varies. Baryonic feedback also needs separate treatment: the backend allows corrections to matter-bispectrum models, explicitly rejects applying them to its TATT calculator, and the shipped emulator design has no baryon coordinates. [Ct option](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/modules/fastnc_interface.py#L96-L105); [training design](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/config/emulator/designs.yaml#L18-L25).

## Fisher forecasts require covariance and prior definitions

The data directory contains a specification, not the survey measurements or covariance matrices. It requires two-point data with source distributions, aperture data, and a joint covariance including cross-correlations. Neither a supplied covariance nor its simulation count can be inferred from the package name. The default joint module retains cross-covariance and cuts the covariance with the same masks as the data vectors. A Y3 or Y6 forecast should retain that behavior unless omitting correlations is an explicitly labeled diagnostic. [Data requirements](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/data/README.md#L1-L45); [masking and cross-covariance](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/modules/joint_likelihood.py#L67-L98).

Two defaults need attention before interpreting a forecast. The [prior file](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/config/priors/des-y6-priors.ini#L1-L18) explicitly supplies placeholder independent shear-calibration widths of 0.01 and redshift-shift widths of 0.02. Those are not established survey priors. Also, although `Map3Data` reads the FITS `NSIM` header, [likelihood setup](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/modules/map3_likelihood.py#L27-L34) obtains the simulation count from an option whose default is −1, treating the covariance as exactly known. The input record must specify which correction is intended and verify consistency with the file; merely storing `NSIM` is insufficient.

For a fixed Gaussian covariance, the familiar Fisher calculation is

```math
F_{ab}=D_a^{\mathsf T}C^{-1}D_b+P_{ab},\qquad
D_a=\frac{\partial\boldsymbol m}{\partial p_a},
```

where $`P`$ is prior precision. The [summary script](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/scripts/fisher_summary.py) warns that the sampler output already includes its Gaussian priors. Additional priors must supply independent information. Fixing a nuisance parameter removes its allowed variation; marginalizing it lets it absorb some of the data response. Their different uncertainties should never be mixed when comparing Y3 with Y6 or two-point with joint forecasts.

A further check concerns the optional Percival likelihood. The [implemented expression](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/desy6_3pcf/likelihood.py#L43-L50) is $`\ln L=-m\ln[1+\chi^2/(N_s-1)]/2`$, with $`m`$ its defined exponent and $`N_s`$ the simulation count. At zero residual its local curvature is $`mD_a^{\mathsf T}C^{-1}D_b/(N_s-1)`$. The module returns the unscaled inverse covariance on this path. [Chapter 16](16_fisher_execution_checks.md) inspects a pinned CosmoSIS sampler and establishes that it consumes this matrix directly: selecting the optional likelihood with valid counts does not make that sampler compute the likelihood's zero-residual curvature. This finding is conditional on the inspected versions and settings; it does not identify the published run's environment or affect the Gaussian default.

Tests should enforce the simulation-count domains of the covariance corrections, not merely positive counts. Both surveys require derivative step convergence and a positive-semidefinite Fisher matrix with any null directions diagnosed. Invertibility is required only on the retained identifiable parameter subspace, including explicitly stated priors; a physically unconstrained parameter need not acquire artificial information. The $`A_2=0`$ fiducial supplies a specific test because its physical mean has no local response to the quadratic redshift exponent. The emulator must respect that limit within its calibrated numerical error.

## What to accelerate, and the information needed from Rafael

The [README reports](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/README.md#L126-L165) approximately a minute for a brute-force NLA evaluation and tens of minutes with about 10 GB for TATT. These are author-reported costs without a matched machine/configuration comparison here. They cannot be combined with the user's approximately 40-second, ten-core example to infer a speedup. They do motivate inspecting concurrency and memory before timing anything. The C design should share cosmology and geometry preparation, reuse forward transforms, assign independent transform outputs to workers, and use SIMD for contiguous arithmetic as described in Chapters 3, 7, and 8.

There is a useful source-only memory estimate at the adapter boundary. The Y6 triangle grid contains $`25^2\times100=62{,}500`$ cells. Four complex double arrays require 4,000,000 bytes per tomographic triplet. Twenty outputs occupy about 80 MB; five complex aperture-weight rows occupy about 20 MB. These estimates exclude intermediate transform tables and allocation overhead. They show that the quoted 10 GB cannot be explained by final natural components alone. Streaming completed components into the aperture contraction can cap output storage, while shared interpolation and transform tables address a different memory cost. The current package already caches aperture weights, so the proposed speed gains must come from additional reuse and parallel work deeper in the calculation.

The following questions should be answered in the written input specification before numerical work begins; no contact with Rafael has been made for this review.

1. Which pinned commits, environment, configurations, and saved reference arrays define the published Y3 NLA inference and the separate TATT paper's mean predictions and response figures?
2. Which Y6 measurements, source distributions, calibration priors, scale cuts, and covariance products define the intended forecast? Which of these are provisional?
3. Which IA terms, `Ct` choice, baryon treatment, alignment subtraction, power-spectrum prescription, and sign convention must agree across the brute-force and emulated calculations?
4. Which simulation counts and covariance-likelihood correction apply to each survey, and are there matching two-point–three-point cross-covariances after any compression?
5. Where are trained networks, metadata, validation vectors, and the configuration behind the reported timings stored? Do their training targets match the pinned source and the requested aperture radii?

The implementation should use one numerical interface and two explicit survey specifications. Y3 supplies the published NLA inference target and a separate Fisher forecast; the TATT paper supplies physical predictions and response figures rather than a claimed published TATT joint inference. Y6 supplies its own forecast target with its own evidence and assumptions. Retaining the existing Python calculations makes this division testable before the C engine becomes the default path.
