# Second source pass: the estimator, transform boundaries, and mutable inputs

> **Archive status.** This source study records design proposals and validation requirements, not completed features. Read the [maintained implementation status](../threepcf.md) first. Both the mean and its covariance belong in `cosmolike/3pcf/`; earlier destination proposals using `fastnc/` or `covariances/` are superseded.

The second inspection found additional behavior that changes the validation plan. The first pass identified several real dependencies, but did not establish that the default prediction equals the measured finite-bin estimator, that all object settings are isolated, or that the numerical boundary options are safe. These questions need explicit answers before a C translation becomes the reference for either Y3 or Y6.

This chapter rereads the pinned TATT revision `7b2336ce37a909bed51f07f32a2a4f096e71b6ce`, main revision `e59eab5a07401d2f484bfe00dd48827f2d2162c7`, and Y6 package revision `fd59fe4fee694d359453d5f573d6a4a55a47a812`. It reports source behavior and algebraic consequences. No packages were imported, numerical predictions executed, or performance measurements made. A source discrepancy is separated below from an unmeasured effect on a survey result.

## 1. Averaging over a bin and evaluating at its center are different operations

The TATT transform averages the two radial coordinates through `two_Bessel_binave`, but reconstructs the opening-angle dependence with `exp(i M phi)` evaluated at supplied angles. The Y6 adapter supplies opening-angle bin centers. There is no angular-bin integral in that reconstruction. This matters because increasing the angular-mode cutoff can improve the point prediction while making the difference between a point and a bin average more visible. [Radial averaging and angular reconstruction](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/fastnc.py#L366-L408), [Y6 centers](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/modules/fastnc_interface.py#L82).

For a uniform angular bin of width $`\Delta\phi`$ centered at $`\phi_c`$, one Fourier mode obeys

```math
\frac{1}{\Delta\phi}\int_{\phi_c-\Delta\phi/2}^{\phi_c+\Delta\phi/2}
e^{iM\phi}\,d\phi
=e^{iM\phi_c}\frac{\sin(M\Delta\phi/2)}{M\Delta\phi/2}.
```

The ratio tends to one for the zero mode. With 100 bins over $`[0,\pi]`$, the mode $`M=100`$ has ratio $`2/\pi`$. This is a statement about one basis function, not a 36% error in the data vector: the actual importance depends on that mode's amplitude, subsequent rotations, and aperture weights. Main's numerical reconstruction also evaluates phase factors at points, so adopting main does not automatically supply angular-bin averaging. [Main reconstruction](https://github.com/git-sunao/fastnc/blob/e59eab5a07401d2f484bfe00dd48827f2d2162c7/fastnc/threepcf/threepcf.py#L798-L820).

There is a second averaging question. TATT first averages X-projected natural components over radial bins and then multiplies by a centroid-rotation factor evaluated at the representative triangle. If the measurement rotates each triangle before averaging, the desired quantity is $`\langle Q\Gamma_X\rangle`$, whereas this operation gives $`Q_{\rm rep}\langle\Gamma_X\rangle`$. The phase $`Q`$ depends on triangle shape and generally varies inside a bin. Uniformly scaling both sides leaves the phase unchanged; independently varying the two sides changes their ratio and does not have that protection. This issue exists even after the separate main/TATT phase-sign question is resolved. [Order of operations](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/fastnc.py#L369-L432).

The required test should start with one known angular harmonic in X projection, then compare direct integration of the rotated field over a bin with the current sequence. Finally repeat for physical natural components and the actual TreeCorr measurement weights. A single empirical shift of the representative separation cannot establish equivalence of these operators. A corrected averaging-and-aperture operator could still be prepared once and reused across cosmologies; this is an opportunity for persistent arrays that also improves the estimator definition.

## 2. The Y6 configuration repair isolates only one dictionary

The Y6 helper correctly replaces each object's `config_IA` dictionary. However, TATT's base class also stores `config_interp`, `config_multipole`, and `config_losint` as class dictionaries, and `update_config` mutates its argument. The transform class similarly shares its bin, FFT, and multipole dictionaries. Therefore the earlier observation that the NLA flag was isolated must not be read as isolation of the complete predictor. [Base defaults](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/bispectrum.py#L68-L86), [mutation](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/utils.py#L117-L128), [transform defaults](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/fastnc.py#L72-L92).

A concrete construction sequence exposes the risk. A TATT object sets the inherited interpolation choice `puv_grid=True`. A subsequently constructed matter object in the Y6 adapter supplies no explicit `puv_grid=False`, so it can inherit that choice and construct perimeter-grid attributes. Its later `compute` requests the ordinary matter path, whose interpolation preparation accesses `r_interp`, `u_interp`, and `v_interp`. The source thus contains an order-dependent attribute mismatch. The supplied combined setup constructs matter before TATT, which avoids this particular first-construction sequence; it does not protect a second pipeline built in the same interpreter. [Adapter construction](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/desy6_3pcf/fastnc_backend.py#L174-L201), [grid selection](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/bispectrum.py#L185-L241), [later grid access](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/bispectrum.py#L920-L927).

Future tests must construct NLA, TATT, and source-kernel objects in both orders, repeat setup, and vary numerical grids between objects. Compare both stored settings and predictions with fresh processes. A C port needs owned configuration and explicit dependencies for every prepared array; copying only the NLA workaround would leave the wider problem intact.

## 3. Input domains and ownership need a written numerical contract

**The redshift Jacobian has a hidden lower boundary.** TATT builds distances at 100 points between redshift zero and five, estimates $`dz/d\chi`$ between adjacent points, and interpolates that derivative on their midpoints with zero outside the interpolation domain. The first midpoint is $`5/198\simeq0.02525`$. Consequently the Jacobian supplied below that redshift is zero, although the physical derivative is finite. Both the NLA and TATT source weights use it and subsequently normalize the resulting distribution. The final spline may introduce additional behavior between its source nodes; the confirmed statement is that its input Jacobian has this artificial cutoff. [Distance preparation](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/bispectrum.py#L348-L356), [NLA use](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/bispectrum.py#L478-L485), [TATT use](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/bispectrum.py#L526-L531).

The effect could be small for a source distribution with negligible nearby galaxies, but that must be tested with the actual distributions and their allowed photo-z shifts. Compare against the background model's direct $`H(z)/c`$ Jacobian with the required distance-unit conversion. Track normalization and source-weight differences before inspecting the final aperture vector. Merely adding more line-of-sight integration nodes does not repair a different, fixed derivative table.

**Resampling nonlinear power can hide unavailable wavenumbers.** The Y6 adapter resamples $`\log P_{\rm nl}`$ onto the linear spectrum's log-wavenumber grid using `np.interp` without an explicit exterior prescription. Queries beyond the nonlinear input range receive constant endpoint log-power values. The downstream IA reader then regards the extended linear grid as its power-spectrum support. Equal array lengths have been achieved, but the additional values have not been supplied by the nonlinear model. [Resampling](https://github.com/rchgomes/desy6-3pcf/blob/fd59fe4fee694d359453d5f573d6a4a55a47a812/desy6_3pcf/fastnc_backend.py#L221-L225), [IA power lookup](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/ia_bispectra.py#L106-L129).

Require an explicit common-support check. Record which $`k=\ell/\chi`$ queries use interpolation or extrapolation, and their contribution to retained observables. Extend the supplied spectra and compare derivatives; testing only the fiducial amplitude would miss a boundary-dependent response. The wrapper's resampling addresses the older shared-`k`-array mismatch, but requires this further physical-domain check.

**Linear-power normalization changes the caller's array.** Both TATT's IA calculator and Halofit retain the supplied linear-power array and apply an in-place normalization to its requested $`\sigma_8`$. Main's Halofit retains this behavior; the newer model wrapper's `np.asarray` does not guarantee a copy. This is confirmed ownership behavior, not proof of an incorrect normalization. It matters when an adapter supplies the same array to several predictors or later compares it with an allegedly unchanged external reference. [TATT mutation](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/ia_bispectra.py#L38-L77), [main mutation](https://github.com/git-sunao/fastnc/blob/e59eab5a07401d2f484bfe00dd48827f2d2162c7/fastnc/bispectrum/halofit.py#L51-L102).

The comparison must record the normalization factor and verify whether input arrays change. A future C interface should either promise immutable caller inputs or explicitly document a writable transfer. Otherwise the same pointer can refer to physically different spectra without any external invalidation tag changing.

**A projected NLA contribution need not be positive.** The matter interpolation path stores `log(bk)`, even when its radial kernels include NLA. Each effective kernel is a lensing contribution plus a signed IA contribution; their product has no general positivity guarantee. TATT's separate IA interpolation already uses signed values. A zero crossing of the total NLA-projected bispectrum would therefore distinguish the two representations. This is a domain requirement to test across the allowed IA priors, not a claim that the published fiducial vector crossed zero. [Logarithmic matter interpolation](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/bispectrum.py#L949-L994). Compare direct and interpolated calculations through deliberately chosen sign changes; do not replace a physical negative value by a numerical floor.

## 4. Main changes grid placement as well as filtering

The two grid tuners do not merely choose different array lengths. TATT fits an even Fourier grid inside the requested Fourier interval and places requested real-space bins at matching samples. Main expands the Fourier interval when necessary and places the first requested real-space bin at index zero of its unpadded grid. Thus the smallest retained angle lies at a different position relative to the transform boundary, and a Fourier interpolation table covering exactly the originally requested interval may no longer cover the tuned grid. [TATT tuning](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/fastnc.py#L829-L902), [main tuning](https://github.com/git-sunao/fastnc/blob/e59eab5a07401d2f484bfe00dd48827f2d2162c7/fastnc/hankel/grid.py#L152-L189).

Neither placement is proved inaccurate by inspection. Compare the actual Fourier endpoints, output endpoints, phase parameter `xy`, padding, and retained indices before comparing transformed values. The first pass's description of TATT's `nfft` as a minimum also needs a qualification: its odd-length adjustment rounds down, so a strict minimum is not guaranteed in every configuration. Main rounds upward in the tuned route.

The already identified filter correction remains valid, but it exposes another boundary case. Both branches retain a taper formula whose denominator is `n_cut−1`; when the integer cutoff is one, its endpoint is `0/0`. Main now returns those filtered coefficients. This is outside the usual large-grid default, but directly relevant to small analytic tests and configurable window widths. Separately, nonzero logarithmic extrapolation takes the logarithm of the transform input, although coupled angular kernels may be signed. Zero padding does not have that positivity requirement. [Taper endpoints](https://github.com/git-sunao/fastnc/blob/e59eab5a07401d2f484bfe00dd48827f2d2162c7/fastnc/hankel/twobessel.py#L285-L300), [signed-input extrapolation](https://github.com/git-sunao/fastnc/blob/e59eab5a07401d2f484bfe00dd48827f2d2162c7/fastnc/hankel/twobessel.py#L316-L338).

The transform contract should state allowed taper cutoffs, whether extrapolation supports signed functions, and how very narrow bin widths are handled. The bin-average factor contains `exp(u)−1`; its evaluation should use a stable small-argument expression and the removable limiting value when its denominator vanishes. Test these limits independently from physical cosmology. [Bin-average factor](https://github.com/git-sunao/fastnc/blob/e59eab5a07401d2f484bfe00dd48827f2d2162c7/fastnc/hankel/twobessel.py#L276-L282).

## 6. Main has further transform work that a C design could share

Main deduplicates complete transformed results by keys containing the coupled input, Bessel orders, and total spin. However, distinct output keys can share the same coupled input. Each call constructs a new `two_Bessel` object, so deduplication of complete outputs does not provide the forward-transform reuse across different Bessel orders that the historical TATT loop already has. Cache the biased forward coefficients by input and transform-grid identity, then apply the different inverse kernels. Preserve main's existing output deduplication as well. [Main output-key loop](https://github.com/git-sunao/fastnc/blob/e59eab5a07401d2f484bfe00dd48827f2d2162c7/fastnc/threepcf/threepcf.py#L647-L669), [object construction](https://github.com/git-sunao/fastnc/blob/e59eab5a07401d2f484bfe00dd48827f2d2162c7/fastnc/hankel/wrapper.py#L47-L54).

The wrapper also makes separate real and imaginary transforms whenever the input has complex dtype. The production prefactor `(-1j)**Sigma` gives a complex-typed integrand even when the spin sum and real scalar-source kernel make its imaginary part exactly zero. Such a case still takes the imaginary transform path. A C implementation can distinguish mathematically real inputs from general complex inputs, avoiding a transform of a known zero array. It must not discard a small imaginary physical component merely because it looks negligible. These are identifiable operations to remove; their contribution to total runtime remains unmeasured. [Complex branch](https://github.com/git-sunao/fastnc/blob/e59eab5a07401d2f484bfe00dd48827f2d2162c7/fastnc/hankel/wrapper.py#L85-L95), [production prefactor](https://github.com/git-sunao/fastnc/blob/e59eab5a07401d2f484bfe00dd48827f2d2162c7/fastnc/threepcf/threepcf.py#L659-L668).

## 7. Prepare shared disk tables before parallel processes start

TATT's file-lock helper does not retain or return the locked file handle. In ordinary CPython execution that local handle is released on return, before the surrounding save or load operation; the unlock helper opens a different handle. Loading an NPZ archive can defer reading its arrays until after the wrapper returns. Those helpers therefore do not establish the intended protected cache transaction. This is a reason to prepare coupling tables serially before launching a Fisher campaign, rather than assume separate processes alone make cache creation safe. [Lock helpers](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/utils.py#L13-L37), [later array access](https://github.com/git-sunao/fastnc/blob/7b2336ce37a909bed51f07f32a2a4f096e71b6ce/fastnc/coupling.py#L168-L183).

Main provides an explicit read-only cache policy, which is useful for that preparation boundary; it should not be described as proof that arbitrary concurrent cache writers are supported. [Main cache policy](https://github.com/git-sunao/fastnc/blob/e59eab5a07401d2f484bfe00dd48827f2d2162c7/fastnc/coupling/cache.py#L128-L143).

The immediate validation priorities are the finite-bin estimator, configuration isolation, and input-domain accounting. Optional diagonal and conversion helpers then need their focused tests. Only after those comparisons should transform reuse and parallel timing be credited as improvements to a scientifically equivalent prediction.
